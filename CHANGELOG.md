# История версий «НСРЗ. Заказ запчастей»

Нумерация — семантическая: МАЖОРНАЯ.МИНОРНАЯ.ИСПРАВЛЕНИЕ. Версия сервера и сайта — в `backend/package.json` и `/api/health`, версия мобильного приложения — в `mobile/pubspec.yaml`.

## 1.2.1 — 16.10.2026 (исправления по итогам мониторинга)

Сервер и сайт — 1.2.1, мобильное приложение — 1.1.1.

**Исправлено**
- Мониторинг считал перезапуск сервера при выкатке версии простоем (доступность 96,7 % вместо 100 %). Теперь `deploy.ps1` отмечает окно плановых работ (`data/monitoring/maintenance.jsonl`), и проверки в нём не входят в расчёт доступности — как в SLA. Окна показываются на странице «Мониторинг».
- В приложении выбранная тема обращения была белым текстом на светлом фоне — плохо читалась. Цвет задан явно (тёмная терракота).

## 1.2.0 — 16.10.2026 (этап 7, поддержка и развитие)

Сервер и сайт — 1.2.0, мобильное приложение — 1.1.0 (новый экран «Помощь и обратная связь»; приложение 1.0.0 продолжает работать).

**Новое**
- **Техподдержка:** обращение «Помощь» на сайте, «Вопрос по заказу» на странице заказа, «Помощь и обратная связь» в профиле приложения; темы — вопрос, вопрос по заказу, ошибка, предложение. Номер обращения ОБР-000…, письмо отделу продаж, ответ сотрудника приходит заказчику по SMS/почте и виден в «Мои обращения».
- **Панель «Обращения»:** очередь со счётчиками (новые / в работе / решено), карточка обращения с контактами и заказом, «Взять в работу», «Ответить и закрыть». Значок с числом новых обращений в меню.
- **Мониторинг** (раздел панели для администратора): состояние системы, доступность в рабочее время против цели ТЗ 99 %, время ответа API (медиана, p95, p99), ошибки 4xx/5xx, запросы по минутам, самые медленные запросы, журнал ошибок сервера, инциденты, резервные копии. Письмо администратору при 5 и более ошибках сервера за 5 минут.
- **Сторож доступности** `scripts/monitor.mjs`: раз в минуту проверяет сервер и адрес в интернете (в обход VPN ПК, как телефон пользователя), пишет журнал и инциденты в `data/monitoring`; запускается из `start-server.cmd`.
- Выкатка: `deploy.ps1` обновляет клиент базы данных (`prisma generate`); дымовой тест — 19 проверок (мониторинг, обращения).
- База данных: таблица `support_tickets` (миграция `20261016180000_support_tickets`).

## 1.1.0 — 16.10.2026 (этап 6, релиз)

Сервер и сайт — 1.1.0, мобильное приложение — 1.0.0 (без изменений, полностью совместимо: API не менялся).

**Новое**
- Ежедневное автоматическое резервное копирование базы (ТЗ п. 4.4): копия при запуске сервера и раз в сутки, `data/backups`, 14 последних; `npm run db:backup`, `npm run db:restore`. Время последней копии — в `/api/health`.
- Строгая политика безопасности содержимого (CSP) для сайта.
- Загрузка остатков из файла предупреждает, если остаток стал меньше резерва по заказам.
- Сценарий выкатки `scripts/deploy.ps1` и дымовой тест `qa/smoke/smoke.mjs`.

**Исправлено** (реестр — `docs/Этап 5 - Тестирование и контроль качества.md`)
- Д-01 подмена IP-адреса заголовком X-Forwarded-For обходила ограничение частоты запросов.
- Д-02 одновременные попытки ввода кода проверялись сверх лимита в 5 попыток.
- Д-03 CSV-инъекция в экспорте заказа и шаблоне остатков.
- Д-04 фильтр категории сбрасывался, если выбрать его в первые 0,3 с после ввода в поиск.
- Д-05 второй сотрудник при повторном подтверждении заказа получал непонятную ошибку.
- Д-06 ссылка на несуществующую компанию давала ошибку 500.
- Д-07 администратор мог отключить сам себя и последнего администратора.
- Д-09 символы `%` и `_` в поиске работали как шаблон.
- Д-10 одновременные запросы кода на один номер отправляли несколько SMS.

## 1.0.0 — 15–16.10.2026 (этап 4, разработка)

Первая рабочая версия: сервер NestJS + PostgreSQL, сайт для ПК с панелью НСРЗ, мобильное приложение Flutter (Android — APK, iPhone — веб-версия «На экран Домой»), вход по коду, каталог с поиском, корзина и заказ с резервом остатков и защитой от повторов, статусы заказа, загрузка остатков CSV/Excel, статистика, журнал уведомлений, доступ из интернета через туннель tuna.
